A second opinion for coding agents

The model that wrote it can't be the one that approves it.

A small, copy-pasteable harness: a fresh-reviewer skill that stress-tests a plan before code exists, and independent judges that return a hard PASS / FAIL on the result. No framework. Apache-2.0.

What's inside

Two parts, usable separately. The review core keeps the logic honest; the design tools keep the UI from looking auto-generated.

A · Review core

The goldfish skill

Fresh subagents — no conversation history — each on one lens (comprehension, architecture, YAGNI, contradictions, readiness) tear into a plan before you build. Prompt + process only.

skills/goldfish/
A · Review core

Security judge

An independent model reads a repo's routes, middleware, schema and actions and returns a gate: broken authz/BOLA, IDOR, injection, hardcoded secrets, PII exposure.

judges/factory-judge.mjs
B · Design

Design judge

Screenshots a live URL and asks a vision model: own identity, or a generic AI template? Scores hierarchy, polish, brand, readability.

judges/design-judge.mjs
B · Design

Design-system generator

Deterministic CSS tokens: same app name → same theme, different names → distinct themes. No API key, no network.

design/gen-design-system.mjs

One contract: the exit code is the gate

Both judges print a JSON verdict to stdout and use their exit code as the CI gate. Independence from the authoring model is the entire point.

PASS exit 0 FAIL exit 1 ERROR exit 2 
# independent review of a repo — fails CI on any critical/high finding
cp .env.example .env   # GITHUB_TOKEN + OPENROUTER_API_KEY (or GROQ_API_KEY)
node judges/factory-judge.mjs owner/repo main

# is the UI distinctive, or a generic template?
node judges/design-judge.mjs https://your-app.example.com

# a unique, repeatable theme from a name
node design/gen-design-system.mjs "My App" --> :root { ... } CSS tokens
